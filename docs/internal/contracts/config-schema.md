# config-schema: config.toml の仕様

`~/.config/zrush/config.toml`(`$XDG_CONFIG_HOME` 優先。cli-protocol.md 参照)の
テーブル・キー・型・既定値・検証規則。この文書が真実であり、コードはこれに追従する。

設定の反映はプロンプト表示ごとの mtime 確認による自動反映(明示リロードなし)。
ファイル不在は正常で、全既定値で動作する。

## [display]

| キー | 型 | 既定値 | 制約 | 意味 |
|---|---|---|---|---|
| `max-lines` | 整数 | `10` | 1〜1000 | 候補一覧の最大行数(表示時はプロンプトと入力行を 1 行確保するため、さらに `$LINES - 1` でクリップ) |
| `delay-ms` | 整数 | `30` | 0〜10000 | バッファ変化から収集開始までのデバウンス遅延。0 は即時。正の値の分解能は 10ms(zselect のセンチ秒精度): 10ms 単位に切り捨て、最小 10ms |
| `min-input` | 整数 | `0` | 0〜100 | 一覧表示を開始する現在語の最小文字数(空の引数語は長さ 0。空バッファは別規則で常に対象外) |

## [display.highlight]

一覧の装飾。値は zsh の highlight 指定文字列(`region_highlight` の spec:
`standout`, `bold`, `underline`, `fg=blue,bold` など)をそのまま zsh へ渡す。

| キー | 型 | 既定値 | 意味 |
|---|---|---|---|
| `selected` | 文字列 | `"standout"` | 選択中セルの装飾 |
| `match` | 文字列 | `"underline"` | マッチ箇所の装飾(match-text 表示時のみ。選択中セルには適用しない) |
| `heading` | 文字列 | `"bold"` | グループ見出し行の装飾 |

- 検証は「文字列であること」まで。spec の解釈は zle に委ねる(不正な spec は zle が無視する)。
- **空文字列は「装飾なし」**(region_highlight エントリを追加しない)。

## [matching]

| キー | 型 | 既定値 | 制約 | 意味 |
|---|---|---|---|---|
| `mode` | 文字列 | `"typo"` | `"prefix"` / `"substring"` / `"typo"` | マッチ強度。後のものほど広く拾う(意味論は cli-protocol.md) |
| `smart-case` | 真偽値 | `true` | — | クエリが全小文字なら大文字小文字を無視 |

## [insert]

| キー | 型 | 既定値 | 制約 | 意味 |
|---|---|---|---|---|
| `tab` | 文字列 | `"menu"` | `"common-prefix"` / `"menu"` / `"insert"` | Tab の挙動: 共通接頭辞を挿入(伸びなければ先頭候補を確定挿入)/ 選択メニューに入る / 先頭候補を即挿入 |
| `trailing-space` | 真偽値 | `true` | — | 確定時に末尾スペースを付与(候補が `-S` 等の接尾辞を持つ場合、およびディレクトリ候補の合成 `/` が付く場合は付与しない) |

## [keybind]

| キー | 型 | 既定値 | 意味 |
|---|---|---|---|
| `select-next` | 文字列 / 文字列の配列 | `["down", "ctrl-n"]` | 選択開始 / 次候補(表示順 = 列優先グリッドの列内下方向) |
| `select-prev` | 文字列 / 文字列の配列 | `["up", "ctrl-p"]` | 前候補(先頭候補では選択解除) |
| `select-left` | 文字列 / 文字列の配列 | `["left", "ctrl-b"]` | 選択中のみ: 左の列へ(グリッド行数ぶん戻る。グループ範囲でクランプ) |
| `select-right` | 文字列 / 文字列の配列 | `["right", "ctrl-f"]` | 選択中のみ: 右の列へ(グリッド行数ぶん進む。グループ範囲でクランプ) |
| `confirm` | 文字列 / 文字列の配列 | `["enter"]` | 確定(挿入のみ。実行しない) |
| `dismiss` | 文字列 / 文字列の配列 | `["ctrl-g"]` | 却下(一覧を閉じる) |

- 割り当て可能なアクションはこの 6 つのみ。
  Tab は `[insert].tab` の挙動に従う(`menu` のときは選択開始キーを兼ねる)ため独立アクションにしない。
- **1 アクションに複数キーを割り当てられる**。単一の文字列は 1 要素配列と等価。
  - 配列指定は既定リスト全体の**置き換え**(既定へのマージはしない)。
  - 空配列 `[]` は「キーを割り当てない」(そのアクションの無効化。有効な指定)。
  - 無効な記法・Tab キー(`^I`)の要素は**要素単位**で捨てて警告する。
    非空の指定から有効な要素が 1 つも残らなかった場合は既定リストへフォールバックして警告。
  - 配列内の重複(正規化後)は除去して警告。
  - 配列の要素が文字列でない場合、その要素を捨てて警告(他の要素は有効)。
    全要素が捨てられた非空の配列は、上記の既定リストフォールバックに従う。
- `select-left` / `select-right` を含む全アクションは原則として**選択中のみ**キーを奪う。
  例外として `dismiss` は非選択でも一覧表示中なら一覧を閉じる。
  非選択かつ一覧非表示なら前任者チェーンへフォールバックする。
  それ以外の非選択時は前任者チェーンへフォールバックするため、既定の ← → / ctrl-b / ctrl-f は
  カーソル移動、ctrl-p / ctrl-n は履歴移動のまま(ctrl-n は ↓ と同じ優先順位規則に従う)。
- **Tab キー(`tab` / `ctrl-i`、正規化後 `seq:^I`)をアクションに割り当てることはできない**
  (該当要素を捨てて警告する。
  zsh 側は ^I を常に固定の Tab 挙動フックに束縛するため、黙って上書きされる事故を防ぐ)。
- `dismiss` の既定は `ctrl-g`(Escape 単独は `\e` プレフィックスと曖昧で
  KEYTIMEOUT 待ちが発生するため既定にしない。ユーザーが明示設定することは可能)。

### キー記法

小文字で書く。修飾は `ctrl-` / `alt-` を前置(`alt` は ESC プレフィックス送出を仮定)。

| 記法 | 正規化結果(cli-protocol.md の形式) |
|---|---|
| `a`〜`z`, `0`〜`9`, 記号 1 文字 | `seq:<その文字>`(ただし `^` は `seq:\^`、`\` は `seq:\\` — bindkey のキャレット/バックスラッシュ記法として誤解釈されないようエスケープして出力する) |
| `ctrl-a`〜`ctrl-z` | `seq:^A`〜`seq:^Z` |
| `ctrl-space` | `seq:^@` |
| `alt-<文字>` | `seq:^[<文字>`(`<文字>` が `^` / `\` の場合は単字形式と同じエスケープを適用: `alt-^` → `seq:^[\^`) |
| `enter` | `seq:^M` |
| `tab` | `seq:^I` |
| `escape` | `seq:^[`(前述の曖昧さ注意) |
| `space` | `seq:" "` 相当(空白 1 文字) |
| `up` / `down` / `left` / `right` | `key:up` など(zsh が `$terminfo[kcuu1]` 等+CSI/SS3 両系統で解決) |
| `shift-tab` | `key:shift-tab`(`$terminfo[kcbt]`) |
| `home` / `end` / `pgup` / `pgdn` / `delete` | `key:<名前>`(terminfo 解決) |

- 上記にない記法は検証エラー(該当要素を捨てて警告。[keybind] の要素単位規則を参照)。
- 同一キーを複数アクションに割り当てた場合は検証エラー(後勝ちにせず、関与した全アクションを
  既定リストへ戻して警告。意図しない上書きの黙認を避ける)。**比較は正規化後の値で行う**
  (`enter` = `ctrl-m` = `^M`、`tab` = `ctrl-i` = `^I` を同一キーとして検出する)。
  既定リスト同士は互いに素なので、この解決は必ず収束する。
- `key:` 形式の terminfo 解決は zsh 側で行うため、Rust の検証は記法の妥当性まで。
  端末の terminfo に該当エントリが無い場合(例: `$terminfo[kcbt]` が空)、
  zsh 側はそのキーの bindkey をスキップして警告する(他のキーは通常どおり適用)。

## 検証とエラーの扱い

- config ファイルが存在しない場合は正常として警告せず、全既定値で動作する。
  それ以外の読み取り失敗(権限エラーなど)は警告を出し、全既定値にフォールバックする。
- **起動は決して失敗させない**。検証は項目単位で行い、不正な項目のみ既定値にフォールバックする:
  - 型不一致(文字列に整数など)/ 制約違反(範囲外・未知の列挙値)/ 未知のキー・未知のテーブル(typo 検出のため警告対象)
  - TOML 構文エラーの場合のみファイル全体を不正として全既定値で動作
- 各エラーは `ZRUSH_CFG_WARNINGS` に 1 件 1 メッセージで出力する(cli-protocol.md)。
  メッセージは「どのキーが・なぜ・どの値にフォールバックしたか」を 1 行で含む。
  例: `config: [display] max-lines: expected integer 1..1000, got "abc"; using default 10`
- **表示先とタイミング(zsh 側の責務)**: config を(再)読み込みしたプロンプト表示時に、
  警告配列を 1 行ずつ stderr へ表示する。再読み込みは mtime 変化時のみ行われるため、
  config が変化しない限り同一警告が再表示されることはない(毎プロンプトのスパム防止)。
