# 001-prototype 実装計画

## 背景と目的

現行の marlonrichert/zsh-autocomplete には、頻繁な破壊的変更・細部動作の不安定さ・設定不能な挙動(`~` の勝手な展開、Tab での過剰な補完挿入、あいまい入力が補完されない、キーバインド設定不可)への不満がある。これを置き換える自分専用ツール zrush を作る。

元アイディアのドキュメントは [`idea/`](idea/)([design.md](idea/design.md) / [config.md](idea/config.md))にある。

このプランのゴールは、元アイディア([idea/design.md](idea/design.md))のフェーズ 1 に相当する **日常投入可能な最小形** を完成させること:

- リアルタイム候補一覧(入力に追従してプロンプト下に自動表示)
- あいまいマッチ(前方一致/部分一致/誤字許容)
- `config.toml` による設定(表示・マッチング・挿入確定・キーバインド)
- 候補一覧からの簡易選択(上下移動 + 確定/却下)

環境: zsh 5.9 / macOS (arm64)。Linux 対応・配布は非目標。

## 決定事項

計画時の相談で確定した方針:

| 項目 | 決定 | 補足 |
|---|---|---|
| スコープ | フェーズ 1 相当を日常投入品質で作る | 使い捨てスパイクにはしない |
| 候補の非同期収集 | **zpty 方式** を本命 | zpty 上の内部シェルで compsys を走らせ候補を吸い出す(fzf-tab に実績)。成立しない場合のフォールバックはバックグラウンド子シェル + `zle -F` |
| 候補一覧の描画 | **`zle -M`** | 最も安全でプロンプト位置を乱さない。ハイライト等の自由度は低いが、描画層は後で差し替え可能な構造にする |
| 候補一覧の操作 | 簡易選択まで含める | 上下キーで候補を選び Enter/Tab で確定。本格的な Tab メニュー選択・履歴メニューはフェーズ 2 |
| あいまいマッチ実装 | 既存クレート活用 | fuzzy 部分は実績あるクレート(候補: `nucleo-matcher`)、誤字許容は必要に応じて自前ロジックで補完 |
| プロセスモデル | 常駐デーモンなし | キー入力ごとに Rust CLI を都度起動。速度不足が実測されたときのみデーモン化を検討 |

元アイディアからの引き継ぎ決定([idea/design.md](idea/design.md) / [idea/config.md](idea/config.md) 由来):

- 「勝手に何かをしない」原則はコードに固定し、設定項目にしない(`~` 非展開、明示操作なしの書き換え禁止)。
- 設定は `~/.config/zrush/config.toml`(XDG 準拠)に一元化。zstyle 面は作らない。
- 既定値: 一覧 10 行、表示遅延 50ms、min-input 0。
- キーバインドは人間可読記法(`"ctrl-n"`, `"shift-tab"`, `"up"` など)で書き、Rust が zsh キーシーケンスに変換する。
- 設定はプロンプト表示ごとに mtime を確認して自動反映。明示のリロードコマンドは不要。
- 不正な設定値でも起動は止めず、該当項目を既定値にフォールバックし、その旨が分かるエラー表示を出す。
- コマンド別オーバーライドはフェーズ 2 検討事項。

## アーキテクチャ

```
┌─ zsh (zsh/zrush.zsh) ────────────────────────────────┐
│ zle ウィジェット群                                     │
│  ├ 入力フック (自己挿入/削除をラップ)                   │
│  ├ zpty 内部シェルで compsys を実行し候補を収集(非同期)│
│  ├ 候補確定・却下・選択移動                            │
│  └ zle -M で候補一覧を描画                             │
└──────────┬───────────────────────────────────────────┘
           │ 都度起動 (stdin/stdout, NUL 区切り)
┌──────────▼───────────────────────────────────────────┐
│ Rust CLI: zrush                                       │
│  ├ zrush match   … 候補列+クエリ → マッチ・ランキング  │
│  ├ zrush config  … config.toml → zsh が source できる  │
│  │                 設定値・bindkey 定義を出力           │
│  └ (内部) config パース / fuzzy / ランキング / キー変換 │
└──────────────────────────────────────────────────────┘
```

- **zsh 側の責務**: zle 統合、compsys 呼び出し(zpty)、描画、キーバインドの適用。
- **Rust 側の責務**: あいまいマッチング、ランキング、`config.toml` の解釈、キーバインド記法→zsh シーケンス変換。
- **入力を決してブロックしない**: 候補収集は zpty 内で非同期に行い、完了を `zle -F` で検知して再描画する。収集中もキー入力は通常どおり処理される。
- zsh↔Rust の入出力仕様は `docs/internal/contracts/cli-protocol.md` として M2 で確定させる(候補は NUL 区切りで stdin、クエリ・文脈は引数、出力はランク済み候補列、を想定)。

## マイルストーン

リスクの大きい順に潰す([idea/design.md](idea/design.md) の「非同期収集という最大の技術リスクを最初に潰す」に従う)。

### M1: zpty による compsys 候補収集の技術検証(最大リスク)

- zpty 上の内部シェルで compsys を走らせ、現在の編集バッファに対する補完候補を吸い出す zsh スクリプトを書く。
- 検証項目: 候補が正しく取れるか(ファイル名 / コマンド名 / git サブコマンド / オプション)、大量候補(数千件)でも入力がブロックされないか、`~` を含む入力が展開されずに扱えるか。
- 成立しない場合はバックグラウンド子シェル方式に切り替え、この plan を更新する。
- 成果: 検証用スクリプトと、収集方式の結論を `notes-zpty.md`(このディレクトリ)に記録。

### M2: Rust コア

- `cargo init`。`zrush match` / `zrush config` サブコマンドの骨組み。
- `config.toml` パース: 表示(max-lines / delay-ms / min-input / ハイライト有無)、マッチング(強度: prefix / substring / typo、smart-case)、挿入・確定(Tab 挙動、末尾スペース)、キーバインド。不正値は既定値フォールバック+警告出力。
- マッチング: `nucleo-matcher` を評価して採用可否を決め、前方一致/部分一致/誤字許容の 3 モードとランキングを実装。
- キーバインド記法変換(`"ctrl-n"` → `"^N"` など)。
- ここまでを純粋ロジックとして単体テストを整備。
- 成果: `docs/internal/contracts/cli-protocol.md`(zsh↔Rust プロトコル)を作成。

### M3: 統合 — リアルタイム候補一覧

- キー入力(自己挿入・削除)ごとに: M1 の方式で候補収集 → `zrush match` でランキング → `zle -M` で一覧描画。
- 表示遅延(既定 50ms)・min-input・max-lines を config から適用。
- 収集・マッチ中も入力がブロックされないことを確認。

### M4: 選択・確定・挿入

- 上下キーで候補選択、Enter/Tab で確定、Escape 等で却下(キーはすべて config のキーバインド定義から適用)。
- Tab の挙動を config で制御(共通接頭辞のみ挿入 / メニューへ入るだけ / 即挿入)。
- 確定時の末尾スペース付与の有無を config で制御。

### M5: 日常投入と仕上げ

- 設定の mtime 自動反映(プロンプト表示ごと)。
- 設定エラー時のフォールバック表示。
- zsh-autocomplete を無効化し zrush に切り替えて日常利用開始。気になった挙動をこのディレクトリの `notes-dogfooding.md` に記録し、チューニング。
- 確定した仕様を `docs/internal/specs/`(挙動仕様・config スキーマ)へ昇格。`docs/user/` に導入・設定ドキュメントを作成。

## 受け入れ条件

[idea/design.md](idea/design.md) の完了条件+簡易選択の追加分:

1. zsh-autocomplete を無効化し、zrush だけで日常のシェル操作ができる。
2. 入力中、候補一覧がプロンプト下に自動表示され、大量候補でも入力がブロックされない。
3. `~` を含む入力が勝手に展開されない。
4. あいまいな入力(タイプミス・部分一致)でも目的の候補に到達できる。
5. 候補一覧から上下キーで候補を選び、確定・却下できる。
6. `config.toml` で候補一覧の行数・表示遅延・キーバインドを変更でき、次のプロンプトから自動反映される。
7. 不正な設定値でも起動が止まらず、既定値フォールバックが分かるエラー表示になる。
8. Rust 側のマッチング・ランキング・設定パース・キー変換に単体テストが存在し、通っている。

## 検証方法

- **Rust コア**: `cargo test`(マッチング・ランキング・config パース・キー変換の単体テスト)。
- **zsh 統合**: 手動確認。`zsh -f` から zrush だけを読み込む検証用起動スクリプトを `zsh/` に用意し、受け入れ条件 1〜7 をチェックリストとして確認する。
- **非ブロック性**: 候補数千件のディレクトリ(生成する)で連続タイプし、入力の取りこぼし・遅延がないことを体感確認。

## 未解決事項(実装中に判断)

- zpty 収集の詳細(内部シェルの初期化内容、ユーザーの compinit 設定の引き継ぎ方)— M1 で決定し `notes-zpty.md` に記録。
- 誤字許容マッチの具体アルゴリズム(nucleo-matcher で足りるか、編集距離ベースの補完が要るか)— M2 で決定。
- `zle -M` で表示できる情報量の限界(選択中候補の示し方など)— M3/M4 で決定。不足なら POSTDISPLAY 方式への差し替えを検討(描画層は分離しておく)。
