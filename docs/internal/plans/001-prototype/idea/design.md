# zrush Design

## Purpose

zsh-autocomplete を置き換える自分専用の zsh 補完ツール **zrush** を Rust + zsh スクリプトで実装する。入力に追従するリアルタイム補完一覧・履歴メニュー/絞り込み・Tab メニュー選択・あいまい(誤字許容)マッチを備え、全挙動を `config.toml` で制御でき、上流依存なしで安定して日常利用できる状態が最終ゴール。本 design の完了ラインはフェーズ 1(下記)まで。

## Context

- 動機: 現行 marlonrichert/zsh-autocomplete の、頻繁な破壊的変更・細部動作の不安定さ・設定不能な挙動への不満。
- 直したい具体的挙動: `~` が勝手に展開される、Tab で過剰に補完挿入される、あいまいな入力が補完されない、キーバインドが設定できない、設定全般がやりづらい。
- 環境: zsh 5.9 / macOS (arm64)。Linux 対応は非目標。自分専用で配布も非目標。
- 現行の好み設定(移植時の初期値の参考): 候補一覧 10 行、表示遅延 0.05s、min-input 0(`.zshrc` の zstyle 設定より)。
- 速度要件: zsh-autocomplete と同等以上でよい(現状に体感の不満はない)。ただし入力は決してブロックしないこと。
- 候補生成は zsh の compsys(既存補完関数)を流用する。コマンド個別の補完定義は書かない。
- 未解決(実装時に判断してよい): compsys 候補の非同期収集方式(zpty / バックグラウンド子シェル等)、候補一覧の描画方式(`zle -M` / POSTDISPLAY / 独自描画)。判断基準は「入力をブロックしない」「プロンプト位置を乱さない」。

## Related Files

- `config.md` — `config.toml` の設定面(設定項目・キーバインド記法・リロード方式)の決定を持つ。

## Direction

- 構成: zsh 側は zle ウィジェットとしてキー入力・compsys 呼び出し・描画の接点を持ち、キー入力ごとに Rust CLI を都度起動して候補列とクエリを渡し、あいまいマッチ・ランキング済みの結果を受け取る。常駐デーモンは作らない(速度不足が実測されたときの後続手段)。
- Rust 側の責務: あいまいマッチング、ランキング、履歴検索、`config.toml` の解釈。zsh 側の責務: zle 統合、compsys 呼び出し、描画。
- 「勝手に何かをしない」原則: 明示操作なしに入力内容を書き換えない。`~` は展開しない。Tab の挿入量(共通接頭辞のみ・選択確定時のみ等)は設定で制御する。
- 設定の真実は `config.toml` に一元化する。キーバインドも TOML で宣言し、zsh 側は Rust が解釈した結果を反映する。zstyle による設定面は作らない。
- 段階導入: フェーズ 1 = リアルタイム補完一覧+あいまいマッチ+TOML 設定の最小形で日常投入(非同期収集という最大の技術リスクを最初に潰す)。フェーズ 2 以降 = 履歴メニュー/絞り込み、Tab メニュー選択、設定項目の拡充。
- Rust 側のマッチング・ランキング・設定パースは UI から分離した純粋ロジックとして単体テスト可能に保つ。zle 統合・描画は手動確認でよい。

## Completion Conditions

- zsh-autocomplete を無効化し、zrush のリアルタイム補完一覧とあいまいマッチだけで日常のシェル操作ができる。
- 入力中、候補一覧がプロンプト下に自動表示され、大量候補でも入力がブロックされない。
- `~` を含む入力が勝手に展開されない。
- あいまいな入力(タイプミス・部分一致)でも目的の候補に到達できる。
- `config.toml` で候補一覧の行数・表示遅延・キーバインドを変更でき、反映される。
- Rust 側のマッチング・ランキング・設定パースに単体テストが存在し、通っている。
