# zrush Config

## Purpose

zrush の挙動を制御する `config.toml` の設定面(何が設定でき、どう書くか)を定める。試行錯誤したい挙動が再ビルドなしに調整でき、設定ファイルを読めば zrush の振る舞いが把握できる状態が目標。

## Context

- [design.md](design.md) のコンパニオン。「設定の真実は TOML に一元化し zstyle 面は作らない」という決定を受ける。
- 原則系の挙動(`~` 非展開、明示操作なしに入力を書き換えない)は設定項目にせずコードに固定する(決定済み)。設定は「調整したくなる可能性のある項目」に限定する。
- 既定値は現行の好み設定に合わせる: 一覧 10 行、表示遅延 0.05s、min-input 0。
- 配置は XDG 準拠の `~/.config/zrush/config.toml`。
- コマンド別オーバーライド(例: git のときだけ一覧行数を変える)はフェーズ 1 では作らない。必要性が実利用で見えたときのフェーズ 2 検討事項。

## Direction

- 設定カテゴリは 4 つ+キーバインド(フェーズ 1 は履歴以外):
  1. **表示** — 一覧の最大行数、表示までの遅延 (ms)、表示を開始する最小入力文字数、マッチ箇所のハイライト有無。
  2. **マッチング** — あいまいマッチの強度(前方一致のみ/部分一致/誤字許容)、smart-case の有無。
  3. **挿入・確定** — Tab の挙動(共通接頭辞のみ挿入/メニューへ入るだけ/即挿入)、確定時の末尾スペース付与の有無。
  4. **履歴**(フェーズ 2) — 並び順、重複の除去、絞り込み対象(先頭一致/全文)。
- キーバインドは人間可読記法(`"ctrl-n"`, `"shift-tab"`, `"up"` など)で書き、Rust 側で zsh のキーシーケンスに変換する。zrush の全アクション(候補の移動・確定・却下・履歴メニュー起動など)に割り当て可能にする。
- 設定はプロンプト表示ごとに mtime を確認して自動反映する。明示のリロードコマンドは不要。
- 項目を増やしすぎない。原則系は固定という方針のとおり、「調整する見込みが薄い項目」はまず固定値で入れ、必要になってから設定化する。

## Completion Conditions

- 上記カテゴリの各項目が `config.toml` で変更でき、既定値が現行の好み設定と一致する。
- 全キー操作が TOML のキーバインド定義だけで変更でき、人間可読記法が受理される。
- 設定ファイルの変更が次のプロンプトから自動で反映される。
- 不正な設定値があっても起動は止まらず、該当項目が既定値にフォールバックしたことが分かるエラー表示になる。
