## 気になった挙動

### 2026-07-27 / mac — 選択マーカー(`> `)で一覧全体がずれ、ちらつく

- 状況: 選択に入ると一覧全体が `> ` の幅だけずれる。選択中も操作のたびにずれ・ちらつきが目につく。
- 期待と実際: 期待は zsh-autocomplete 同等の背景色ハイライト(レイアウトが動かず、選択位置は色で分かる)。実際はマーカー方式でレイアウトが動き、「表示が不安定」という印象が道具への信頼感を下げる。ずれを解消しても(常時字下げ等)マーカー方式では視認性が不足で、期待水準に達しない。
- 備考: `zle -M` 内で ANSI が使えない制約による設計どおりの挙動(plan.md)。使用をためらうレベル。
- 対処: 002-display-layer D1(`feat(zle): replace listing render with POSTDISPLAY + region_highlight`)で
  選択表示を standout ハイライトに置換(レイアウト不動)。体感確認待ち。

### 2026-07-27 / mac — ctrl+p / ctrl+n で選択移動できない

- 状況: 選択中に ctrl+p / ctrl+n を押しても候補移動にならない(既定は ↑↓ のみ)。
- 期待と実際: 手癖では上下移動は ctrl+p/n であり、既定で ↑↓ と同様に選択移動に効いてほしい。config の `[keybind]` で変えられるだけでは不足(既定値の問題)。使用をためらうレベル。
- 対処: `[keybind]` を 1 アクション複数キー(文字列 / 配列)に拡張し、既定を
  `["down","ctrl-n"]` / `["up","ctrl-p"]`(select-left/right も `ctrl-b`/`ctrl-f` を追加)へ変更
  (`feat(keybind): multi-key actions with emacs-style defaults`)。体感確認待ち。

### 2026-07-27 / mac — 候補が縦一列で走査しづらい

- 状況: 候補が 1 行 1 候補の縦一列で表示される。
- 期待と実際: 一覧を選択メニューとして使うとき、目的の候補を目で探す走査がしづらく、プロンプト下の縦占有も大きい。期待は zsh-autocomplete のような複数列グリッド(一覧性が高く、縦に短い)。使用をためらうレベル。
- 対処: 002-display-layer D2(`feat(display): column-major grid listing and select-left/right`)で
  列優先グリッド+←→の列移動を実装。体感確認待ち。

### 2026-07-27 / mac — 種別見出し・グループ化がない

- 状況: 候補の種別(ディレクトリ / ファイル / オプション等)の見出し・グループ化がなく、種別混在で並ぶ。
- 期待と実際: 見ただけで種別が判別できず、同種がまとまらないので目的の候補を探しにくい。期待は zsh-autocomplete の `directory` / `file` のような見出し付きグループ表示。使用をためらうレベル。
- 対処: 002-display-layer D3(`feat(display): group headings with per-group grids`)で
  見出し付きグループ表示を実装(fork 内 zstyle でグループ情報を取得)。体感確認待ち。

### 2026-07-27 / mac — 打鍵ごとの遅延感と、一覧が一瞬消えるチラつき(速度要件未達)

- 状況: 入力中、打鍵のたびに一瞬の遅延感がある。候補一覧は打鍵のたびに一瞬消えてから描き直され、その空白の瞬間がチラつきとして見える。発生場面の切り分け(候補の多寡・環境差)は未実施。
- 期待と実際: 期待は速度要件どおり「zsh-autocomplete と同等以上」(plan.md)。実際は zsh-autocomplete より遅く感じ、かなり使いにくい。速度要件未達。使用をためらうレベル。
- 未切り分け: 遅延が「打った文字のエコー自体」なのか「一覧の更新」なのかは体感では区別できていない。前者なら「入力を決してブロックしない」原則(受け入れ条件 2「体感遅延なし」)の違反になるため、切り分けが必要。
- 仮説(備考): 「一覧をいったん消してから描き直す」更新モデルは、空白期間が遅延として可視化される点で、遅さの体感とチラつきの両方を生んでいる可能性がある。zsh-autocomplete は旧一覧を残したまま置き換えるため空白が見えない。
- 対処: 002-display-layer D1 の置き換え更新モデルで空白を排除。D5 の計測で
  打鍵パス上の恒常コスト(タイマー fork)は最大 0.4ms/打鍵と判明し仮説 b は棄却
  (計測記録は 002 plan.md)。残る体感遅延の有無をドッグフーディングで判定する。

上記 5 件はすべて「使用をためらう」レベル(M5 完了条件に直接かかる)。ctrl+p/n を除く 4 件は `zle -M` 描画層に起因する共通根を持つ。制約(ANSI 不可・縦一列・見出しなし)に加え、全消し再描画という更新モデルがチラつきと遅延の体感を生んでおり、期待水準(背景色ハイライト・複数列グリッド・見出し付きグループ・空白の見えない更新)は個別の小修正では届かない。フェーズ 2 送りにしていた描画層差し替え(POSTDISPLAY + region_highlight)が M5 のブロッカーになっている、という発見。
描画層差し替え(遅延の切り分け含む)は `../002-display-layer/plan.md` で対応する。
ctrl+p/n の既定キーバインドは 002 のスコープ外(1 アクション複数キーのスキーマ拡張を伴うため 001 側で別途対応)。
