# 002-display-layer 実装計画

## 背景と目的

M5 ドッグフーディング(`../001-prototype/notes-dogfooding.md`)で「使用をためらう」問題 5 件を記録した。
うち 4 件は `zle -M` 描画層に共通根を持つ:

- 選択マーカー(`> `)で一覧全体がずれ、ちらつく(期待: 背景色ハイライト)
- 候補が縦一列で走査しづらい(期待: 複数列グリッド)
- 種別見出し・グループ化がない(期待: 見出し付きグループ表示)
- 全消し再描画の空白がチラつきと遅延の体感を生む(期待: 空白の見えない更新)

`zle -M` の制約(ANSI 不可・全消し再描画)により、これらは個別の小修正では期待水準に届かない。
001 でフェーズ 2 送りとしていた **POSTDISPLAY + region_highlight への描画層差し替え**
(001 plan.md「未解決事項」に前倒し条件として明記済み)を実施し、M5 ブロッカーを解消する。

位置付け: **001-prototype の M5 を完了させるための子作業**。
M5 の完了判定・ドッグフーディング記録は 001 側(`notes-dogfooding.md`)に置いたまま。
本計画の完了時に、001 plan.md の描画関連記述と contracts を最新の姿に更新する。

## 要求(ドッグフーディング由来)

1. **選択候補は背景色系ハイライトで示す**。レイアウトは選択の出入り・移動で 1 桁も動かない(マーカー方式は廃止)。
2. **複数列グリッド表示**。一覧性を上げ、プロンプト下の縦占有を減らす。
3. **種別見出し付きグループ表示**。compadd のグループ情報(`-X`/`-J`/`-V`。M1 でレコード捕獲済み)を使う。
4. **空白の見えない更新**。打鍵しても旧一覧が消えてから描き直される瞬間が見えない。
5. **マッチ箇所ハイライト**。差し替えと同時に設定ごと導入する(001 の決定の履行)。
6. **打鍵遅延の切り分けと解消**。差し替え後に残る打鍵ごとの遅延を計測し、
   残るなら原因(入力エコーのブロック疑い)を特定して解消する。速度要件は「zsh-autocomplete と同等以上」。

## スコープ外

- **ctrl+p / ctrl+n での選択移動(ドッグフーディング 5 件の残り 1 件)**。
  描画層と独立、かつ「1 アクション複数キー割り当て」という config スキーマ拡張
  (現行は 1 アクション 1 キー)を伴うため、001 側の M5 作業として別途対応する。
- 履歴メニュー、本格的な Tab メニュー選択、コマンド別オーバーライド(フェーズ 2 のまま)。
- 候補の説明文(compadd `-d`)のグリッドでの見せ方の作り込み
  (フェーズ 1 同様、display-text があればそれを表示する、以上のことはしない)。

## 決定事項

- **描画先** — POSTDISPLAY + region_highlight。`zle -M` は廃止する。
  - 一覧テキストは改行 1 つを先頭に付けて `POSTDISPLAY` に置く(バッファ全体の後ろに表示される)。
  - 装飾(選択行・マッチ箇所・見出し)はすべて `region_highlight` で行う。
    オフセットは `$#BUFFER` 以降が POSTDISPLAY 領域(zsh-autosuggestions と同方式)。
    POSTDISPLAY にエスケープ列は書かない(バッファ表示の一部であり、そのまま表示されるため)。
  - `region_highlight` エントリには `memo=zrush` を付ける(zsh 5.9+。
    z-sy-h 0.8+ が自他のエントリを区別するための公式メカニズム)。
- **更新モデル** — 「消してから描く」をやめ、**POSTDISPLAY の置き換え**にする。
  - 新しい一覧文字列を作って一度で代入する。zle の再描画は 1 回の画面更新になり、空白期間が見えない。
  - 選択移動は region_highlight の差し替えのみ(テキスト不変)で行い、最小コストにする。
  - 消去(候補 0 件・却下・確定・accept-line)は `POSTDISPLAY=` と自エントリの region_highlight 除去。
    `zle -M` と違い明示消去が必須(`zle-line-finish` での消去は現行どおり。
    確定・実行後の画面に一覧が残らないことを検証項目にする)。
- **グリッドレイアウトの責務** — zsh 側(描画の責務)。プロトコルは変えない。
  - レイアウト対象は表示件数(最大 max-lines 行 × 列数)だけなので zsh のループで足りる。
  - 幅計算は表示幅ベース(`${(m)#...}` / `${(ml:...:)}`)。
    現行の文字数ベース切り詰めによる全角崩れ(M5 チェックリスト項目)もこれで解消する。
  - 充填は**列優先**(ls 型: 表示順が列内を下に進む)。
    select-next/prev の 1 次元移動が「列内の下/上移動」と自然に一致するため。
  - 各行は `$COLUMNS` 未満に切り詰めて折り返しを起こさせない。行数は max-lines と `$LINES` でクリップ(現行踏襲)。
- **候補の取得件数** — グリッド化で表示容量が max-lines 件を超えるため、
  zsh は `zrush match --max-lines` に「max-lines × 列数の上限見積もり」を渡す。
  プロトコル上の意味は元々「出力する最大候補数」なので版番号は変えない。
- **グループ表示** — レコード既載の `X`(見出し文字列)/`J`/`V`(グループ名)を使う。
  - ランキングは現行どおりグローバル(Rust は変更なし)。表示時に zsh がグループへ振り分け、
    グループの順序は「所属候補の最良ランク順」、グループ内は ランク順とする。
  - 見出し行は選択対象外。見出しなし候補は先頭に見出しなしで置く。
  - 見出しの文言(X と J/V のどちらを優先するか・重複整理)は実装中に実物で決める(未解決事項)。
- **選択キー** — select-next / select-prev の意味は「表示順の次/前」(列優先なので列内上下)のまま。
  グリッドの水平移動用に **select-left / select-right アクションを追加**する(既定: left / right)。
  - 現行ディスパッチと同じく「選択中のみ」奪い、非選択時は前任者チェーンへ(カーソル移動を壊さない)。
  - config-schema.md にアクション 2 つを追加(D2 で更新)。Tab キー予約規則は不変。
- **マッチ箇所ハイライト** — Rust だけがマッチ位置を知っているため、**プロトコルを拡張**する。
  - `zrush match` の stdout を「各 index の後にマッチ位置フィールド」を伴う形に変え、
    **PROTOCOL_VERSION を 2 に上げる**(cli-protocol.md を D4 で更新)。
  - 位置は match-text へのバイト範囲リスト(例: `0-1,3-4`。なしは空フィールド)。
    zsh 側は表示文字列上の該当範囲を region_highlight に変換する
    (display-text 表示時・切り詰め時は範囲外をスキップ)。
- **ハイライト設定** — `[display.highlight]` テーブルを新設し、差し替えと同時に導入する。
  - 値は zsh の highlight 指定文字列(region_highlight の spec: `standout`, `fg=blue,bold` など)を
    そのまま受け渡す。Rust の検証は「文字列であること」まで、解釈は zle に委ねる
    (不正 spec は zle が無視する。検証規則の詳細は D4 で config-schema.md に確定)。
  - キーの絵姿(既定値は実装時に見た目で確定):

    ```toml
    [display.highlight]
    selected = "standout"      # 選択行
    match    = "fg=blue"       # マッチ箇所
    heading  = "fg=green"      # グループ見出し
    ```

- **打鍵遅延の切り分け** — 差し替え完了後に計測で行う(体感の混入源である描画空白を先に除く)。
  - 仮説 a: 全消し再描画の空白が「遅延」として見えていた → 差し替えで解消。
  - 仮説 b: キー入力パス上の恒常コスト。
    最有力はデバウンスタイマーのプロセス置換(`<( zselect ... )`)が**打鍵ごとに現在シェルを fork**
    していること(fork コストは親メモリに比例し mac で特に遅い — M1 計測の知見)。
  - 計測(ZRUSH_LOG のタイムスタンプ + 打鍵〜エコーの実測)で寄与を特定し、
    仮説 b が有意なら修正する(候補: タイマー子プロセスの常駐化・使い回し。設計は計測後に決める)。
    エコー遅延が残るなら「入力を決してブロックしない」原則(受け入れ条件 2)の違反として本計画内で解消する。

## 技術リスクと検証項目

- **zsh-syntax-highlighting との region_highlight 共存**(最大リスク)。
  z-sy-h は pre-redraw で region_highlight を書き換える。zsh 5.9 の `memo=` で区別される想定だが、
  フック順(z-sy-h より前に source する現行構成)込みで、
  選択ハイライト・マッチハイライトが消されない/汚染しないことを実機検証する。
  zsh 5.8(memo= なし)では z-sy-h 併用時にハイライトが劣化し得る。
  劣化許容とするか回避策を入れるかは 5.8 実機確認時に判断(未解決事項)。
- **POSTDISPLAY の画面挙動の同等性**。画面最下部での表示時のスクロール量、端末リサイズ、
  複数行バッファ(継続行)、カーソルが行中(RBUFFER あり)のときの表示位置、tmux 内。
  `zle -M` との差分を検証チェックリストにする。
- **消去パスの網羅**。確定・却下・accept-line・空バッファ化・min-input 未満・候補 0 件の全パスで
  POSTDISPLAY と自 region_highlight が確実に消えること(残骸はドッグフーディングで既知の注意点)。
- **`zle -F -w` ハンドラからの更新反映**。ハンドラ内での POSTDISPLAY / region_highlight 変更が
  即座に再描画へ反映されること(必要なら `zle -R`)。
- **全角混在のグリッド桁揃え**。`${(m)}` 系の表示幅計算で列が揃うこと(M5 チェックリスト項目の前倒し解消)。

## マイルストーン

リスクの大きい順: 共存リスクと更新モデルを最初の縦一列差し替えで潰し、その上に見た目を積む。

### D1: 描画層差し替えの土台(縦一列のまま)

- `zle -M` を廃止し、POSTDISPLAY 置き換え更新+消去パスを実装する(一覧はまだ縦一列)。
- 選択表示をマーカーから背景色ハイライト(`selected`)に置き換える。ずれ・ちらつきの解消を確認。
- z-sy-h / zsh-abbr 共存、画面挙動の同等性、消去パスの網羅を検証(上記チェックリスト)。
- 完了判定: ドッグフーディングの「マーカーずれ」「全消しチラつき」2 件が体感で解消していること。

### D2: 複数列グリッド

- 列優先グリッド+表示幅ベースの桁揃え・切り詰め。
- select-left / select-right アクション追加(config-schema.md 更新、Rust のキーバインド検証追従)。
- 取得件数の見積もり(--max-lines へ渡す値)を実装。

### D3: グループ見出し

- グループ振り分け・見出し行・グループ順序の実装。見出しの文言規則を実物で確定。

### D4: マッチ箇所ハイライトと設定導入

- プロトコル v2(マッチ位置返却)。cli-protocol.md を先に更新し、Rust・zsh を追従させる。
- `[display.highlight]` テーブル導入(config-schema.md 更新、既定値確定)。

### D5: 打鍵遅延の切り分けと解消

- 計測 → 仮説 b(打鍵ごとの fork 等)の検証 → 有意なら修正。
- 完了判定: 打鍵〜エコーの体感遅延がなく、一覧更新の体感が zsh-autocomplete と同等以上であること。

### 完了時

- `notes-dogfooding.md` の該当 4 件+遅延エントリを再確認し、解消したものに `[解決]` を付ける。
- 001 plan.md の描画関連記述(「候補一覧の描画」「マッチ箇所ハイライト」「未解決事項」)を最新の姿に更新。
- AGENTS.md の進行中計画から本計画を外す(M5 継続は 001)。

## 受け入れ条件

1. 選択の出入り・移動で一覧のレイアウトが動かず、選択行が背景色系ハイライトで判別できる。
2. 候補が複数列グリッドで表示され、全角混在でも桁が揃う。
3. 候補が種別見出し付きグループで表示される。
4. 打鍵で一覧が「一瞬消える」瞬間が見えない。
5. マッチ箇所がハイライトされ、`[display.highlight]` の 3 項目が config.toml から変更・自動反映できる。
6. 打鍵〜エコーに体感遅延がなく、速度の体感が zsh-autocomplete と同等以上(ドッグフーディング判定)。
7. 001 の受け入れ条件(非ブロック・`~` 非展開・z-sy-h / zsh-abbr 共存・確定/却下/履歴導線)が
   差し替え後も成立している(検証用スクリプト+実機チェックリストで確認)。

## 未解決事項(実装中に判断)

- グループ見出しの文言規則(`X` と `J`/`V` の優先・重複整理)— D3 で実物を見て決定。
- zsh 5.8(memo= なし)+ z-sy-h 併用時のハイライト劣化の扱い — 5.8 実機確認時に決定。
- 取得件数の見積もり規則(列数上限の決め方)— D2 で決定。
- `[display.highlight]` の既定値と検証規則の詳細 — D4 で config-schema.md に確定。
- 打鍵遅延の修正方式(タイマー常駐化ほか)— D5 の計測後に決定。
